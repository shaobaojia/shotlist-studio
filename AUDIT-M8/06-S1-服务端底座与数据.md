### 中危（2 条）

**B1 · `/api/batch` 绕开场号校验 → 可写空场号 / 造重号（`/api/update` 有，`/api/batch` 没有）**

- **位置**：`server/api/handlers.py:88-100`（`update` 对 `scenes.scene_no` 做 trim / 非空 / 唯一三重校验）v.s. `server/api/handlers.py:110-122`（`batch`）→ `server/core/ops.py:161-182`（`batch_update`）→ `server/core/ops.py:137-139`（`_apply_field` 白名单**含** `scene_no`，探针复核 `write_keys("scenes")` 含 `scene_no`）。
- **机制**：字段级白名单管「能不能写」，没人管「写进去的值合不合法」；场号「非空 + 唯一」这条不变量只活在 `update` 一个入口的 handler 分支里。任何走 `/api/batch` 的写者（当下前端改名走 `/api/update`，**可达但未使用**；将来脚本 / 导入器 / AI 批量都会踩）都能把 `scenes.scene_no` 写成 `""` 或与另一场重号 → `db.scene_by_no` 返回首行，`/api/scenes/s010` 从此有歧义。
- **证据（高度透镜探针 `probes/S1/probe.py`）**：`A1 write_keys('scenes') 含 scene_no: True`；`A2 batch 写空场号: {"changed":1,…'field':'scene_no','changed':True}`；`A3 batch 造重号: 两场同为 s010`。
- **违反规则**：Put behavior with the concept that owns them（校验该在域层）；Consolidate duplicate validation；Preserve error semantics（同一条不变量两个入口两套行为）。
- **修法**：把 `scene_no` 的 trim / 非空 / 唯一做成 `TABLES[table]` 上声明的 per-field 校验、由 `_apply_field` 统一执行；删 handler 里 `:90-100` 的两段特判（`update` / `batch` 从此同源）。与先修 P1（`require_table` 单点）、P2 同批施工。
- **severity：中（可达的破损面，当前无使用者）｜ effort：small-med｜ 来源：高度 BUG-S1-1 + 高度 A03（同机制两处）｜ confidence：high（探针实证）**
- **关联**：reuse 附注 5 的「场号唯一性是 check-then-act（`handlers.py:96-100` 先查后写）」在单用户局域网（`DO_NOT_FLAG A7`）不可达，仅记——校验下沉到 `ops` 后，可在同一事务里再查一次收口。

**B2 · 当日首写并发 →「每日快照」整库备份对同一 `.tmp` 并发写 → 写请求 500**

- **位置**：`server/core/db.py:16-17`（`connect(rw=True)` 每次先调 `ops.ensure_daily_snapshot`）→ `server/core/ops.py:59-70`（`if not dest.exists():` … `os.replace(tmp, dest)`）。
- **机制**：`dest.exists()` 判定与 `os.replace` 之间是 TOCTOU；`tmp` 路径**只按日期命名**（`studio-YYYYMMDD.db.tmp`，无 pid/随机后缀）、无进程内锁、无 `O_EXCL`。前端会并发发起写（自动保存 + 审计重跑 + AI 应用），当天第一个写请求若有两个并发，两线程同时过 `exists()`、同时 `sqlite3.connect(tmp)` 并同时 `backup()` → 一方抛 `OperationalError`，异常从 `db.connect(rw=True)` 直穿到 `app.py:115-116` 兜底 → **该条写请求整体 500**（前端乐观更新回滚、toast「保存失败」）。
- **证据（效率透镜探针 `probes/s1_probe3.py` §1，4 线程同刻屏障起跑、副本库 + 空快照目录）**：`t0/t1/t2 (3/4) OperationalError: attempt to write a readonly database @ ops.py:65 src_con.backup(dst_con)`，`t2: ok made=True`；目录产物仅 `studio-20260923.db`。触发窗口＝每天第一个写请求的同一瞬间；单线程串行正常（首次备份 20 ms，已存在 0.12 ms）。
- **违反规则**：correctness 优先——「判定 + 备份 + 改名」复合动作缺少互斥；`tmp` 名不唯一。
- **修法**：`ensure_daily_snapshot` 用模块级 `threading.Lock`（或 `os.open(tmp, O_CREAT|O_EXCL)`）包住「判定 + 备份 + replace」，锁内复查 `dest.exists()`；`tmp` 名带 pid/随机后缀。顺手加「今日已做过」的进程内布尔，免掉每次写连接的 stat+glob（＝W 项 E9）。
- **severity：中（写入被拒，概率低）｜ effort：small｜ 来源：效率 BUG-S1-1（探针复现栈）｜ confidence：high**
