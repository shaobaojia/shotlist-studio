## 一、真 Bug（4 条，按严重度排序）

> 本批 4 条**均无持久化数据损坏路径**（写库契约归服务端批次）；影响面为**未保存内容被丢弃 / 用户偏好被覆盖 / 样式契约静默失效 / 契约写而无人读**。B1/B2 为静态代码路径（可复现步骤已给，未端到端实测）；B3 静态可判定（无需浏览器）；B4 经聚合复核全量检索。

### 中危（1 条）

**B1 · 配方编辑器关闭设置浮卡不检查脏态 → 未保存的编辑被静默丢弃（同卡「‹ 返回列表」却有二次确认）**

- **位置**：`web/js/settings.js:21-24`（`closeSettings()` 只做 `card.hidden = true` + `floatLeave('panel', closeSettings)`）；对照 `web/js/settings.js:173-176`（`if (viewDirty && viewDirty() && !confirm('有未保存的修改，确定丢弃并返回列表？')) return;`）与 `:136`（`refreshList()` 开头清 `viewDirty`）、`:185`（`viewDirty` 设立）。
- **机制**：配方编辑器是**显式保存**语义（`保存` 按钮 `:193-205`），编辑面挂着长文本。用户在编辑中按 ✕ / 点卡外 / Esc（三条路径都走 `closeSettings`）→ 无脏检查、无提示，整段未保存改动丢掉；下次打开 `loadAll()→refreshList()` 回列表，草稿不可见。同卡内「返回列表」**是**有 `confirm` 保护的——同一份未保存内容在两条退出路径上待遇相反。
- **豁免核对**：`DO_NOT_FLAG A.2` 的「自动保存无保存键」口径只覆盖**分镜表字段**；配方编辑器带显式保存按钮，不属该豁免。
- **修法**：把 `:173-176` 的脏检查提成 `guardLeave()`，在 `closeSettings()` 与 `floatLeave` 的关闭回调里复用（或关闭时把草稿留在 `viewDirty` 并恢复编辑态）。
- **severity：中危（原报 low-med；按「静默丢弃用户输入」上提一档）｜ effort：XS｜ 来源：效率 BUG-F5-2｜ confidence：high（纯代码路径，聚合复核逐行核对）**

### 低危（3 条）

**B2 · 手关的「情绪曲线」被自动开启覆盖，并把该偏好落盘（同场改一个镜头就弹回）**

- **位置**：`web/js/ribbon.js:150-151`（`const hasMood = segs.some(…); if (hasMood && !ST.mood) { ST.mood = true; save(); }`）；关断路径 `:371-377`（开关 `ST[k] = !ST[k]; save(); layout(true)`）；同场重建入口 `web/js/scene.js:302`（`syncLive` → `buildRibbon`），触发白名单 `scene.js:283-288`（`shots.duration` / `shots.shot_size` / `beats.mood_temp` / `beats.name`）。
- **机制**：`ST.mood` 既是持久化偏好（`:17/55/61`）又是「自动显示」闸门。用户点掉开关 → 落盘 false、当帧隐藏；之后**任何一次 `buildRibbon`**（换场，或活体同步＝改任一镜头时长/景别、改节拍情绪温度/节拍名）只要本场还有情绪温度，就自动置真并 `save()` → 曲线回弹、且每次回弹写一次 `localStorage`（同步 IO 落在重建热路径上）。
- **与文档口径偏差**：`AGENTS.md:130` 写的是「手关＝**当场景内**隐蔽，下次切场再出」——实现把「当场景内」扩大成「同场直到下一次重建」，两者不等价。blame `ad0389e3`（挂件带 v2.1 期），注释只写「有数据＝自动显示」，**未写「要落盘」**（对照 `DO_NOT_FLAG A.5`：该区块定案项是「hover 提示 300ms」与「svg 宽度走 CSS 100%」，不含这条）。
- **修法**：① 自动开启只活在会话内（模块级 `let moodAuto`，不写 `ST.mood`；用户手关过就存 `moodOff` 不再自动开）；② 或保留「切场即出」但把 `save()` 从 build 里拿掉。**更彻底**：`ST.mood` 改三态 `'auto'|'on'|'off'`（缺省 `'auto'`），「旧布尔 → 三态」需产品一句话（谁是默认）。
- **severity：低危（本批唯一用户可复现项）｜ effort：XS（三态版 small）｜ 来源：效率 BUG-F5-1 + 高度 BUG-F5-1/A11｜ confidence：high（代码事实链完整，未起服务复现）**

**B3 · `app.css:1002` 的 `color: var(--ink)` 是失效声明：`--ink` 全库未定义**

- **位置**：`web/css/app.css:1002`（`.cmdk-input { … color: var(--ink); }`，git blame `2bf395cb`＝命令面板首次落地那次）。全库（`web/**` js/css/html）`--ink` **仅此 1 处**使用；`:root`（`:5-34`）只有 `--head/--text/--ink2/--dim/--dim2`。
- **后果**：`var()` 引用未定义变量且无 fallback ⇒ 声明在 computed-value 阶段作废，`color` 回落继承（`.cmdk-input` 父链 `.cmdk`→`.cmdk-mask`→`body`，≈`var(--text)` #353026）。观感近等价所以一直没暴露，但这是**静默失效的样式契约**：改 `.cmdk`/`body` 的颜色会意外改变输入框文字色，读代码的人会以为这里指定了颜色。
- **修法**：改 `var(--text)`（若意图「比正文更重」则 `var(--head)`）；顺手在 `:root` 加一行「墨色只有 `--head/--text/--ink2`」的口径注释。CSS 变量存在性检查脚本本批已有（`probes/f5_css_probe.py` C 段）。
- **severity：低危（显示影响极小，属「静默失效」类）｜ effort：1 行｜ 来源：质量 BUG-F5-1 + 复用 BUG-F5-R1 + 高度 BUG-F5-2（三透镜同报）｜ confidence：high（静态可判定）**

**B4 · 审计卡行的 `data-for` 写了没人读：注释声明的联动契约与实跑机制是两条轨**

- **位置**：`web/js/audit.js:183`（`tr.dataset.for = String(row.dataset.id); // 同行标记（筛选隐藏联动，M6）`）v.s. 实际生效的 `web/js/filter.js:102-107`（`while (n && (n.classList.contains('detail') || n.classList.contains('audit-card-tr'))) …` 逐兄弟类名嗅探）。
- **证据（全量检索）**：全库 `data-for` 读写点仅 4 个——`table.js:147`（写 detail 行）、`table.js:245`（读，选择器写死 `tr.detail[data-for="…"]`）、`hotbox.js:113`（读 `dataset.id || dataset.for`）、`audit.js:183`（写审计卡行）。审计卡行同时带 `audit-card-tr` 类，而 `table.js:245` 的读点被 `.detail` 限定**永不匹配审计卡行**；CSS 里也无 `[data-for]` 选择器。即「注释声明的契约」与「实际生效的机制」两条轨并存；当前**无行为差异**（类名嗅探覆盖到了），属潜在错位（下一个附件行类型出现时，改的是 `filter.js` 的 `||` 串而非产出方属性）。
- **修法**：`filter.js:103-107` 的白名单整段换成 `n.dataset.for` 判定（约定「附件行必带 `data-for=<镜头行 id>`」，`table.js:147` 与 `audit.js:183` 已是两个产出点）；或反之删掉这次写入。与 R06/W31 的「行下附属行结构单点」同刀施工。
- **severity：低危（无当前行为影响，契约/维护风险）｜ effort：small｜ 来源：质量 BUG-F5-2 + 高度 A04（同族 F1-8）｜ confidence：high（聚合复核 4 个读写点逐一核对）**
