> 全部为**视图/状态类**错误；本批未发现数据正确性类 Bug（写入路径归服务端批次）。行 id 均属本场，故下述错位均不导致串场写库。

### 高危（1 条）

**B1 · `refreshCurrentView` 无在飞/路由守卫 → 陈旧回包把别场整表写进当前路由（并覆盖全片页）**

- **位置**：`web/js/scene.js:115-123`（`refreshCurrentView`）；触发点 `main.js:285`（全局 Ctrl+Z）、`table.js:449`（＋镜头）、`scene.js:329/162/177/510/525`。对照物：`scene.js:65-68`（`renderScene` 有明确 hash 守卫，说明此处是遗漏）、`main.js:217-228`（`route()` 全片分支从不清理 `currentData`）。
- **问题**：`const no = currentData.scene.scene_no` 在 `await` 之前取；`currentData = await api.scene(no)` 与 `paintScene(view)` 回来后**无任何守卫**——既无 in-flight 序号，也不校验 hash 是否已切走。
  - 表现 a（效率透镜实测复现，两轮独立一致）：打开 `#/s011`（34 镜）→ 点「＋ 镜头」→ 0.4s 后把 hash 切到 `#/s010`（s010 正常渲染）→ 3.2s 后读页面：`hash=#/s010`、导航高亮 chip = `s010 …`，但 `tr.shot` 行数 = **34**、首行 `data-id=1000`、场景头 `.scene-no` = **s011** → s011 的整表被回写到 s010 的路由下；同机制在飞期间切到「全片」会直接清掉全片表。
  - 表现 b（质量透镜静态路径）：在 `#/s010` 改一格（栈非空）→ 点「全片」(`#/`) → Ctrl+Z ⇒ 同一路径把 s010 渲染进 `#view`，而 hash 仍是 `#/`、导航高亮仍指「全片」；此后点「全片」chip 因 hash 相同不触发 `hashchange` ⇒ 卡在「内容是场级页、URL 是全片」的错位态，只能点别的场再点全片。同类触发：全片页右键导航删场后 Ctrl+Z。
- **影响**：视图/路由错位，用户以为在 s010 上操作、看到的却是 s011 的行与数据（幻觉数字/镜号），属**易造成误编辑**的显示级数据事故。
- **修法**：请求即打序号（`const seq = ++_refreshSeq;` 回来 `if (seq !== _refreshSeq) return;`）+ 回来后校验 `currentData && currentData.scene.scene_no === no && hash 指向本场`（退而求其次：照抄 `renderScene` 的守卫）；补 `route()` 进全片分支时清理 `currentData`（后者更彻底，需确认无其他依赖）。
- **severity：高危｜ effort：small-medium｜ 来源：效率(B1, 实测 high) + 质量(B1, 中)｜ confidence：high**

### 中危（3 条）

**B2 · 全局 Ctrl+Z 未排除 Shift → Ctrl+Shift+Z（house 口径＝重做）在编辑器之外执行的是「撤销」**

- **位置**：`web/js/main.js:279-286`。`if (!(e.ctrlKey || e.metaKey) || String(e.key).toLowerCase() !== 'z') return;` —— 按住 Shift 时 `e.key === 'Z'`，`toLowerCase()` 后照样命中，全程无 `e.shiftKey` 检查（对比 `cmdk.js:173` 明确带 `!e.shiftKey && !e.altKey`）。
- **问题**：重做只在编辑面 textarea 上绑（`hotbox.js:417-430`，`ta.addEventListener`；house 口径见 `hbedit.js:1` 与 `hotbox.js:420`）；焦点不在编辑器时（点过格子按 Esc、或全片页）Shift 手势落到全局处理器。空栈时只弹「没有可撤销的操作」（无害），**栈非空时执行了用户没要的撤销**。
- **修法**：全局处理器加 `if (e.shiftKey || e.altKey) return;`（若要支持全局重做，另行接撤销栈的 redo）。
- **severity：中危｜ effort：XS｜ 来源：质量(B2)｜ confidence：high**

**B3 · 场号非 `s\d+` 形态时，命令面板「导出本场」判为「不在场里」（同一 notion 两套 hash 解析）**

- **位置**：`web/js/drawer.js:221-234`（抽屉打开时挂 document 级 capture `mousedown`，目标不在抽屉 frame 内即 `onOutside(e)`）；`scriptdrawer.js:195` 的豁免名单＝`.float-card:not(.scene-freeze), .drawer, #block-manager, #hist-panel, #sel-bar, .ai-diff, [id^="ai-"]`（**缺** `.bcard / #draft-card / .prompt-box / .cell-prompt`）；`hotbox.js:608` 的名单**有**这四项；`float.js:2` 声明「点外豁免单点在 `ui.isFloatTarget()`」，而 `ui.js:76` 只认 `.float-card, .menu`。两抽屉无互斥，可同时打开。

**B8 · 镜号列被隐藏时，平铺视图的「节拍」列会插到整张表最前（表头/单元格列错位）**

- **位置**：`web/js/table.js:66-73`。`const cols = [{key:'__toggle',…}].concat(fields);`（fields 已按 `prefs.hidden` 过滤）→ `const i = cols.findIndex((c) => c.key === 'shot_no');` 镜号被隐藏则 `i === -1` → `cols.splice(i + 1, 0, {key:'__beat',…})` 变成 `splice(0, 0, …)`，插到最前。
