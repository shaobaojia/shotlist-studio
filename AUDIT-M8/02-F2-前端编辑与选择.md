### 中高危（1 条）

**B1 · `batchWrite` 撤销记录用「默认表」、前向写用「逐项表」→ AI 改节拍动作后 Ctrl+Z 写错表（撤销失败 + 栈分叉）**

- **位置**：`web/js/selection.js:313-314`（前向：`table: o.table || table`）vs `web/js/selection.js:330`（撤销记录：`table: table`，即 `opts.table || 'shots'`）。触发链：`cellmenu.js:305-317` 节拍头右键「✦ AI 改写…」→ `aiwrite.js:71`（`{table:'beats', id, field:'beat_action'}`）→ 预览卡 → `aiwrite.js:330` 把 per-op table 放进 ops → `batchWrite(ops, …, {write: api.aiApply})` **未传 `opts.table`**。
- **问题**：前向经注入写口 `aiApply`（表无关）正确落 beats；撤销记录却把每项标成 `table:'shots'`。Ctrl+Z → `api.batch([{table:'shots', id:<beatId>, field:'beat_action', …}])` → 服务端按 shots 白名单拒绝 → 抛错冒泡到 `edit.undo` 弹「撤销失败」；而该 op **已从栈里弹出**（`edit.js:26` `pop()` 在 try 之外）→ 节拍值已改、撤销栈少一条，状态分叉（用户再按 Ctrl+Z 撤到更早的操作）。
- **边界（反证）**：`applyBeatFieldValue`/`applySceneFieldValue` 显式传了 `opts.table`（`selection.js:467/486`）——只有「逐项 table + 不传 opts.table」的组合踩雷，即 AI 通道的节拍项。
- **修法（一行级）**：`back.push({ table: <本项实际写入的表>, … })`——与 313-314 同源（把 `o.table || table` 存进 op 再回读）。
- **证据级别**：静态（前向/反向表选择不对称，调用链完整可读）；**未运行时复现**。复现建议：空场临时节拍 → 右键节拍头 AI 改写 → 应用 → Ctrl+Z，观察 toast 与 beats 表。
- **severity：中高危｜ effort：small｜ 来源：高度(BUG-F2-1)｜ confidence：med-high**

**B3 · 选区拖拽缺「按钮态」护栏：窗口外松键后 `drag` 态永久滞留（且全站文本选择被关闭）**

- **位置**：`web/js/selection.js:47-55`（mousemove 处理器只判 `if (!drag) return;`——全文无 `e.buttons` 检查；探针 `grep buttons` 在本批 7 文件零命中）、`:73-77`（唯一复位点是 document `mouseup`；无 `window.blur`/`mouseleave`/`pointercancel` 兜底，也没有 `setPointerCapture`）、`:60/:77`（`document.body.classList.add('no-select')` 与移除只在进入/离开 mouseup）。
- **后果**：鼠标在窗口外/系统对话框上松开（Chrome 不向页面补发 mouseup）后：① 此后每一次鼠标移动都命中 `drag` 分支 → `cellsOf`+`paint`+`emit` 全跑（叠加 E1/E2/E3 的热路径成本），选区随光标无声扩张；② `no-select` 常驻 → **全站文本选择被关闭**，用户无法复制页面文本且看不出原因。
- **修法**：mousemove 首行 `if (e.buttons !== 1) { /* 视为结束 */ …收尾; return; }`（与 mouseup 共用收尾函数）；或改 `pointerdown` + `setPointerCapture` 拿系统级保底。
- **证据级别**：静态（代码证据充分；「窗口外 mouseup 不补发」是浏览器行为，本批未实测——:8094 禁碰 + 副本起服务超时预算）。质量透镜曾以低置信独立记过同一现象（quality 附注 1），本条按效率透镜的静态证据升格。
- **去重声明**：F1〔efficiency〕4 已报 `table.js:44-64 startColResize` 同类「丢 mouseup」；本条是**不同交互（选区）的新证据 + 附带 `no-select` 全局副作用**，非重复计数。
- **severity：中｜ effort：small｜ 来源：效率(BUG-F2-1) + 质量(附注1)｜ confidence：med-high**

### 低危（2 条）

**B4 · 相机表单保存失败只回滚模型，不回滚表单槽文本（且不重画单元格）**

- **位置**：`web/js/edit.js:367-371`（catch 只做 `cfg.setCam(f, oldVals[f])` + `refreshSiblings()`；表格相机格的 `refreshSiblings`＝`table.js:214-218` 只刷详情行 3 个 kv，**不含 `renderCell`**）；槽文本由关闭时读取的局部变量 `v1/v2/v3` 驱动（`edit.js:275-277/:300` 写 `txt.textContent`），失败路径没有回写这三个局部量。
- **表现**：写失败（服务端白名单拒绝 / 网络抖）→ toast 报错、模型与详情行已回滚，但**仍打开的表单槽里显示的仍是那次未落库的拾取值**；用户以为已改成功，直到关表单（`close()` → `cfg.renderCell()`）才变回旧值。
- **修法**：catch 里同时回写槽文本（`txt.textContent = get()`，或提取 `syncSlots(v1,v2,v3)` 供两路复用）并调 `cfg.renderCell()`。
- **severity：低｜ effort：small｜ 来源：效率(BUG-F2-2)｜ confidence：high（纯代码路径可见）**

**B5 · 粘贴待命窗口内全局 Esc 被抢占（编辑面「Esc 取消」失效）**

- **位置**：`web/js/cellmenu.js:197-204`（`armPaste` 在 document 上挂 **capture** `keydown`，`preventDefault + stopPropagation`，6 秒窗口）。
- **机制**：capture 阶段监听先于目标节点；编辑面的 Esc 监听挂在元素上（`edit.js:176-179`）、选区 Esc 挂在 document 冒泡（`selection.js:124`）——两者都被 `stopPropagation()` 截断。窗口内按 Esc 只取消粘贴，不进格的「取消编辑」。
- **表现**：右键格 →「粘贴（从此格起）」→ 6 秒内双击任意格 → Esc：预期还原原值，实际弹「已取消粘贴」且编辑面仍开。
- **修法**：最小修＝`onKey` 里先判编辑面（`.cell-editor, .cam-editor`）或 `menuOpen()` 让位；正解＝W18（待命态归位为共享状态，Esc 交既有路由）。
- **证据级别**：静态 + DOM 事件序规范；未运行时复现。
- **severity：低｜ effort：small｜ 来源：高度(BUG-F2-2)｜ confidence：med**
