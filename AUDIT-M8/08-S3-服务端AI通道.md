## 一、真 Bug（2 条，按严重度排序）

### 中危（1 条）

**B1 · JSON `true` 被当 1 用：`is_id` 单点在手，接口/域层 7 处手写 `isinstance(x, int)` → 误打第 1 场并发起真实外呼**

- **位置（实测 7 处，聚合期逐行核对）**：`server/api/ai.py:53`（preview `scene_id`）· `:87`（apply `job_id`）；`server/api/draft.py:10`（`scene_id`）· `:23`（`scene_id`/`shot_id`）· `:46`（`job_id`）；`server/core/rewrite.py:72`（目标行 `id`）· `:260`（`item_ids` 元素）——判据单点＝`server/core/prompts.py:20-22`（`def is_id(x)` docstring 明写「非 bool 的 int（JSON true 不得当 1 用）」，4 模块已 import 它）。
- **机制**：`isinstance(True, int)` 为真（bool 是 int 子类）→ 接口守卫放行；SQLite 把 `True` 绑成 `1` → 命中「第 1 场/第 1 镜/第 1 条预览项」。
- **证据（三透镜同报，探针实证）**：`probes/S3/probe_guard.py` / `probe_s3.py`（P3/P4）/ `probes/S3-altitude/s3_probe.py`（桩 chat、内存/探针目录 DB、**零真实外呼**）——
  1. `prompts.is_id(True)` → `False`（单点正确拒绝）而站点用的 `isinstance(True, int)` → `True`；
  2. `SELECT scene_no FROM scenes WHERE id=?` 传 `True` 命中 **`S01`**（实测返回 `('S01',)`）；
  3. `rewrite._load_scene(con, True)` → `scene_id=1 scene_no=s010`；`draft.DraftJobs.start_scene(True, "台本"×20, chat=桩, …)` → **受理**（未抛「场景不存在」）；
  4. `1 in {True} → True` → `{"item_ids":[true]}` 命中第 1 条预览项（`apply_items:259-262` 的 `all(isinstance(x,int))` 同样放行）。
- **后果**：`{"scene_id": true}` 不是 400，而是被当作「第 1 场」——draft/rewrite 会**发起真实外呼**并作用在第 1 场上（`apply_items` 命中即落库 `source=ai` + 写痕迹）；`{"table":"shots","id":true}` 会把镜 1 当改写目标（`rewrite.py:72-83`）。
- **违反规则**：Consolidate duplicate validation；Move rules toward domain objects（通用判据长在提示词域）；「Make public APIs small, explicit, and hard to misuse」。
- **修法**：7 处改走 `prompts.is_id`；更彻底＝判据上移 `core/fields.py`（字段字典＝服务端校验单点）或 `core/db.py`，`core/prompts.py` 保留别名转出，`api/ai.py`、`api/draft.py`、`api/prompts.py`、`core/rewrite.py` 全从一处取；**并在域层入口补守卫**（`DraftJobs.start_scene/start_prompt`、`PreviewJobs.start` 当前域层零判据）。旁证：同仓 `api/audit.py:9-15 _int_q`（`int('true')` 即 raise → 400）与 `api/prompts.py:12-17 _req_int`（走 `is_id`）已是正确口径——**同仓两套行为**。
- **severity：中（按后果：付费外呼 + 误作用第 1 场）；可达性受限（注记）**——前端 `api.js` 恒发数字，只能由脚本/手工请求触发（`DO_NOT_FLAG A7` 局域网单用户下无攻击面）；三透镜自评 **medium（复用）/ low（质量、高度）**，本报告按后果取中危并保留可达性注记 ｜ **effort：small**（7 处替换 + 域层 3 处守卫）｜ **来源：复用 BUG-S3-1 + 质量 S3-Q04 + 高度 A02 / BUG-S3-1（三透镜合并）｜ confidence：high（机制三探针实证）**
- **blame**：`is_id` 生于 `9d94266f`（M3 修复批2，09-20）；AI 域（`2c4e28e5`）与草稿域（`6368453b`）均在**次日**（09-21）新写时用了裸判据——判据已被发明、只在本域落地。

### 低危（1 条）

**B2 · 模型回包用非数组容器包 `beats`/`shots` → 解析器抛 KeyError/TypeError，整任务以 Python 内部消息收场（潜在）**

- **位置**：`server/core/draft.py:29`（`for b in (obj.get("beats") or [])[:MAX_BEATS]:`）· `:49`（`obj.get("shots") or []` 同款）——元素级容错在位（`:30`/`:50` 逐元素 `isinstance(b, dict)` 跳过），**容器级闸门缺失**；异常落到 `:181-182` / `:254`（`except Exception as e: self._finish(job_id, str(e)[:300])`）→ 前端 `web/js/draft.js:229` 显示「生成失败：…」。
- **证据（`probes/S3/probe_s3.py` P1，纯函数、零模型调用）**：`draft.parse_beats('{"beats": {"name":"误发","kind":"🔴 戏点"}}')` → `KeyError: slice(None, 8, None)`；`draft.parse_shots('{"shots": {"beat":1,"blocking":"x"}}', 1)` → `KeyError: slice(None, 40, None)`；`draft.parse_beats('{"beats": 3}')` → `TypeError: 'int' object is not subscriptable`。
- **机制**：模型把数组包成对象（`{"beats": {...}}`）是常见回包形态之一；文件头 `draft.py:24` 声明的口径是「解析（宁缺毋滥）」——元素级做了、容器级没做。用户看到的应是「节拍骨架生成为空——可『重来』」，实得 `slice(None, 8, None)` 这种零可行动信息的串。对照 S2-BUG-1 判词「大门有守卫、小门没有」：这里**连大门都开着**。
- **违反规则**：Isolate invalid-state handling；Preserve error semantics（异常文案泄漏 Python 内部术语）；「Validate at the boundary」。
- **修法（2 行）**：`v = obj.get("beats"); rows = v if isinstance(v, list) else []`（`parse_shots` 同）；`rewrite.parse_items`（`rewrite.py:127`）虽不炸（dict 迭代出字符串键 → 逐元素跳过 → 空结果），也建议同样显式化。
- **severity：低（潜在，需模型异常回包）｜ effort：trivial｜ 来源：质量 BUG-S3-1（探针实证）｜ confidence：high（纯函数实测）｜ relates to 效率 E9（同站点、机制不同：E9 是静默丢弃/改写，本条是崩溃）+ S2-BUG-1（容错面不对称）**
